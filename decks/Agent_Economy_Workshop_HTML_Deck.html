Discover · โครงสร้างที่ agent อ่านออก

4 ประตูที่ทำให้ Agent มองเห็นแบรนด์

1 · Structured Data บนเว็บ

Schema.org (Product, Offer, FAQ), ราคา/สต็อกในรูปแบบข้อความจริง ไม่ฝังในภาพ — พื้นฐานที่ทำได้ทันทีสัปดาห์นี้

2 · เนื้อหาสำหรับ Answer Engines

AEO ที่เรียนใน workshop หลัก — คำตอบชัด อ้างอิงได้ เป็นกลางพอที่ AI จะหยิบไปตอบ + ไฟล์แนะนำ AI เช่น llms.txt

3 · MCP Server ของแบรนด์

สิ่งที่สร้างใน Advanced MCP คือ "หน้าร้านสาขา agent" — เปิดแคตตาล็อก/สต็อก/โปรโมชันให้ AI เรียกตรงอย่างมีสิทธิ์ควบคุม

4 · Agent Card (A2A)

"นามบัตรมาตรฐาน" ที่ประกาศว่า agent ของแบรนด์ทำอะไรได้ เจรจาอะไรได้ ติดต่อทางไหน — ให้ agent ฝั่งลูกค้าค้นพบเราเป็นระบบ

ลำดับใหม่ของ funnel: ก่อนชนะใจลูกค้า ต้องผ่านการคัดกรองของ agent ที่ลูกค้าไว้ใจก่อน

Lab 1: Agent-Readiness Audit — มอง แบรนด์ด้วยตา Agent

ภารกิจทีม (3-4 ท่าน)

  • Step 1 (5 นาที): เลือกแบรนด์ — ของทีมเอง หรือแบรนด์ไทยที่รู้จักดี
  • Step 2 (15 นาที): ใช้ Claude เป็น "agent จำลอง": ให้ค้นเว็บจริงแล้วตอบ — สินค้าหลักราคาเท่าไร มีของไหม ส่งกี่วัน คืนสินค้าอย่างไร มีโปรโมชันอะไร
  • Step 3 (5 นาที): ให้คะแนน 4 ประตู (Structured Data / AEO / MCP / Agent Card) ประตูละ 0-5 ลง worksheet
  • Step 4 (5 นาที): สรุป 1 ประโยค: "สิ่งแรกที่ต้องแก้คือ ______" + แชร์หน้าห้อง

Prompt Starter

"คุณคือ shopping agent ที่ลูกค้าสั่งให้ซื้อ [สินค้า] จากแบรนด์ [ชื่อ] ค้นเว็บจริงแล้วรายงาน: ข้อมูลใดหาเจอ/หาไม่เจอ ราคา สต็อก เงื่อนไขส่ง-คืน และสรุปว่าถ้าท่านเป็น agent จะกล้าสั่งซื้อจากแบรนด์นี้หรือไม่ เพราะอะไร"

สิ่งที่มักค้นพบ

  • ราคาซ่อนใน LINE/DM — agent อ่านไม่ได้
  • โปรโมชันอยู่ในรูปภาพ — มองไม่เห็น
  • นโยบายคืนสินค้าไม่มีเป็นลายลักษณ์

Transact · A2A Protocol

A2A: ภาษากลางให้ Agent ต่างค่ายร่วมงานกัน

1

Agent Card

ประกาศตัวตน+ความสามารถของ agent ในรูปแบบมาตรฐาน — อีกฝ่ายรู้ทันทีว่าคุยเรื่องอะไรได้ ผ่านช่องทางใด

2

Tasks & Artifacts

มอบงานข้าม agent เป็น task ที่ติดตามสถานะได้ ผลลัพธ์ส่งกลับเป็น artifact — เหมือน brief งานระหว่างบริษัท แต่เกิดในวินาที

3

ข้ามค่าย ข้ามเจ้าของ

agent บน Google, Microsoft, AWS หรือของแบรนด์เอง คุยกันได้ด้วยมาตรฐานเดียว — production แล้วใน supply chain, การเงิน, ประกัน

ตัวอย่าง MarTech: agent ของ agency รับ brief "หา influencer สายผิวแพ้ง่าย งบ 200,000" → ค้น Agent Card ของ platform ต่างๆ → เจรจาเรตกับ agent ของ influencer แต่ละราย → สรุป shortlist พร้อมราคากลับมาให้มนุษย์เลือก — ทั้งหมดผ่าน A2A

สถานะ 2026: องค์กรหนุน 150+ ราย ใต้ Linux Foundation — ไม่ใช่ standard war แต่เป็น standard ที่ชนะแล้ว

Transact · AP2 Protocol

AP2: สามลายเซ็นที่ทำให้ Agent จ่ายเงินได้อย่างรับผิดชอบ

Intent Mandate
ลูกค้าเซ็น: "อนุญาตให้ซื้อเซรั่มตัวเดิม งบไม่เกิน 900 บาท ภายในสัปดาห์นี้" — ขอบเขตอำนาจที่มอบให้ agent ชัดเจน ตรวจย้อนได้
Cart Mandate
Agent เซ็น: ตะกร้าที่จัดจริง — สินค้า ร้าน ราคา 890 บาท ส่งพรุ่งนี้ — พิสูจน์ว่าทำตามขอบเขตที่ได้รับ ไม่เกิน ไม่แถม
Payment Mandate
ฝั่งชำระเงินเซ็น: รายการเรียกเก็บจริงที่เครือข่าย payment ประมวล — สามใบต่อกันเป็นสายหลักฐานครบวงจร
ผลลัพธ์
เมื่อมีข้อพิพาท: เทียบ 3 ใบ รู้ทันทีว่าผิดชั้นไหน — ลูกค้าสั่งเกิน? agent จัดเกิน? ร้านเก็บเกิน? — ความรับผิดชอบมีเจ้าของเสมอ

สำหรับแบรนด์: รับออเดอร์จาก agent = ตรวจ mandate ให้เป็น — เหมือนที่เคยเรียนรู้การรับบัตรเครดิตเมื่อ 30 ปีก่อน

Transact · เดินเรื่องเต็มสาย

หนึ่งธุรกรรม สามโปรโตคอล — ใครทำอะไรตรงไหน

1 · ลูกค้า → agent
มอบหมาย + เซ็น Intent Mandate (AP2) — "ซื้อเซรั่มเดิม งบ 900"
2 · ค้นพบร้าน
agent อ่าน structured data + Agent Card ของแบรนด์ (Discover) — คัดเหลือร้านที่ "อ่านออกและเชื่อถือได้"
3 · คุยกับร้าน (A2A)
agent ลูกค้า ↔ agent แบรนด์: เช็คสต็อกจริง ขอโปรสมาชิก ตกลงเงื่อนไขส่ง — ฝั่งแบรนด์ดึงข้อมูลผ่าน MCP server ของตัวเอง
4 · ปิดดีล (AP2)
Cart Mandate → ลูกค้าอนุมัติครั้งเดียว → Payment Mandate → ชำระผ่านเครือข่ายจริง
5 · หลังการขาย
ใบเสร็จ/สถานะส่งของไหลกลับอัตโนมัติ — ข้อมูลเข้าสู่ CDP เป็น first-party data รอบใหม่ (data loop จาก workshop หลัก)

สังเกต: MCP ที่ท่านสร้างเป็นใน Advanced คือ "อวัยวะภายใน" ของ agent แบรนด์ในขั้นที่ 3 — ทุกอย่างต่อกันเป็นระบบเดียว

Trust · ความเสี่ยงใหม่

4 ความเสี่ยงที่ผู้บริหารต้องมองเห็นก่อนเปิดรับ Agent

1 · Agent ปลอมตัว

agent อ้างตัวเป็นลูกค้า/คู่ค้าเพื่อดูดข้อมูลราคา สต็อก เงื่อนไข — ต้องแยกชั้นข้อมูล public/authenticated ให้ชัดตั้งแต่ออกแบบ

2 · Mandate Fraud

ธุรกรรมอ้าง mandate ที่ไม่มีจริงหรือเกินขอบเขต — ฝั่งแบรนด์ต้อง "ตรวจลายเซ็นเป็น" ก่อนรับออเดอร์ agent เสมอ

3 · การแข่งขันที่มองไม่เห็น

แพ้-ชนะเกิดในเสี้ยววินาทีที่ไม่มีมนุษย์เห็น — ต้องมี analytics ใหม่: ถูก agent พิจารณากี่ครั้ง แพ้เพราะอะไร (ราคา? ข้อมูลไม่ครบ? ส่งช้า?)

4 · Narrative อยู่ในมือ Agent

agent เป็นผู้สรุปแบรนด์ให้ลูกค้าฟัง — แบรนด์คุมเรื่องเล่าได้ทางเดียว: คุณภาพและความชัดของข้อมูลที่เปิดให้ agent อ่าน

โครงสร้างรองรับกำลังมา: agent identity, MCP curated registry (Q4 2026), กรอบ PDPA/EU AI Act ที่เรียนไปแล้ว — ผู้เริ่มก่อนอย่างมีวินัยได้เปรียบ

เส้นทางที่เดินมาด้วยกัน — และสิ่งที่ท่านทำได้แล้ววันนี้

1 · AI for MarTech

  • เข้าใจ AI/LLM + C-R-T-F
  • MCP + Integration ระดับผู้ใช้
  • วิเคราะห์ลูกค้า + ออกแบบ architecture
  • LINE Bot ตัวแรก

2 · Advanced MCP

  • เขียน MCP server เอง
  • Security + governance ในโค้ด
  • Deploy ขึ้น cloud ให้ทั้งทีม
  • เห็นภาพ multi-server workflow

3 · Agent Economy (วันนี้)

  • มองแบรนด์ด้วยตา agent
  • เข้าใจ A2A + AP2 ระดับตัดสินใจ
  • Journey + เส้นแดงของธุรกิจตนเอง
  • แผน 90 วันเริ่มได้ทันที
