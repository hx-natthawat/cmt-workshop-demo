## อ้างอิง: Journey 5 ขั้น (หนึ่งธุรกรรม สามโปรโตคอล)

1. **ลูกค้า → agent** — มอบหมาย + เซ็น Intent Mandate (AP2) เช่น "ซื้อเซรั่มเดิม งบ 900"
2. **ค้นพบร้าน** — agent อ่าน structured data + Agent Card ของแบรนด์ (Discover) คัดเหลือร้านที่ "อ่านออกและเชื่อถือได้"
3. **คุยกับร้าน (A2A)** — agent ลูกค้า ↔ agent แบรนด์: เช็คสต็อกจริง ขอโปรสมาชิก ตกลงเงื่อนไขส่ง — ฝั่งแบรนด์ดึงข้อมูลผ่าน **MCP server ของตัวเอง** (คือสิ่งที่สร้างใน Advanced MCP)
4. **ปิดดีล (AP2)** — Cart Mandate → ลูกค้าอนุมัติครั้งเดียว → Payment Mandate → ชำระผ่านเครือข่ายจริง
5. **หลังการขาย** — ใบเสร็จ/สถานะส่งไหลกลับอัตโนมัติ เข้าสู่ CDP เป็น first-party data รอบใหม่

## อ้างอิง: AP2 — 3 Mandates (ลายเซ็นที่ทำให้ agent จ่ายเงินได้อย่างรับผิดชอบ)

| Mandate | ใครเซ็น | ความหมาย |
|---|---|---|
| **Intent** | ลูกค้า | ขอบเขตอำนาจที่มอบให้ agent เช่น "ซื้อเซรั่มเดิม งบไม่เกิน 900 ในสัปดาห์นี้" |
| **Cart** | Agent | ตะกร้าที่จัดจริง — พิสูจน์ว่าทำตามขอบเขต ไม่เกิน ไม่แถม |
| **Payment** | ฝั่งชำระเงิน | รายการเรียกเก็บจริงที่เครือข่าย payment ประมวล |

> เมื่อมีข้อพิพาท: เทียบ 3 ใบ รู้ทันทีว่าผิดชั้นไหน — สำหรับแบรนด์ "รับออเดอร์จาก agent = ตรวจ mandate ให้เป็น"

## Prepare · Readiness Ladder 4 ขั้น (ปิดวัน — โหวตว่าองค์กรอยู่ขั้นใด)

| ขั้น | ชื่อ | ทำอะไร |
|---|---|---|
| 1 | **Readable** — agent อ่านเราออก | structured data, ราคา/นโยบายเป็นข้อความ, AEO — เริ่มสัปดาห์นี้ งบ ~0 |
| 2 | **Connectable** — agent ต่อเราได้ | MCP server + LINE Bot = Advanced MCP + Lab 3 ที่เรียนแล้ว |
| 3 | **Negotiable** — agent เจรจากับเราได้ | Agent Card + นโยบายเจรจา (จาก Lab 2 นี้) |
| 4 | **Transactable** — agent จ่ายเงินเราได้ | รองรับ AP2 mandate ผ่าน payment partner |

> ขั้น 1-2 ไม่ต้องรอใครอนุญาต — เริ่มได้เลย
